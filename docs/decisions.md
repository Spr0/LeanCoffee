## Phase 0 (2026-10-25)

| #   | Decision                                                                                                               | Why                                                                                                                                        |
| --- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| D11 | React 19 instead of React 18.                                                                                          | React 19 is the current stable line and the Vite template default; 18 receives only critical fixes. No dependency in the plan requires 18. |
| D12 | Supabase **publishable key** (`sb_publishable_...`) as `VITE_SUPABASE_PUBLISHABLE_KEY` instead of the legacy anon JWT. | Supabase recommends it for new apps; it rotates independently of the JWT secret. Same public-by-design role.                               |
| D13 | ESLint 9 (not 10).                                                                                                     | `eslint-plugin-jsx-a11y` does not yet support ESLint 10.                                                                                   |
| D14 | `playwright-core` pinned to 1.63.0 via `overrides`.                                                                    | Matches the preinstalled browser and keeps `@axe-core/playwright` types aligned with `@playwright/test`.                                   |
| D15 | gitleaks installed in CI from the release tarball with a SHA-256 check, not the gitleaks Action.                       | No third-party action with repo access; same scanner.                                                                                      |
| D16 | GitHub Actions pinned to commit SHAs.                                                                                  | Supply-chain hardening; Dependabot keeps them current.                                                                                     |
| D17 | Local Supabase config enables anonymous sign-ins.                                                                      | CI database tests need them; production was enabled in the dashboard.                                                                      |

## Phase 1 (2026-10-25)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                     | Why                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D18 | Board secrets (`boards`: code, recovery hash, passcode hash, removed users) are split from public state (`board_state`).                                                                                                                                                                                                                                                                                     | Prompt forbids reading `boards` directly, yet members need live phase and timer state over Realtime. `board_state` is member-readable; `boards` has no grants or policies. |
| D19 | Every streamed table has a surrogate `uuid` primary key.                                                                                                                                                                                                                                                                                                                                                     | Realtime DELETE events carry only the primary key and are not RLS-filtered; natural keys would leak who voted on what.                                                     |
| D20 | Throttling uses an append-only `failed_attempts` table (per-user exponential lockout after 5 failures in 15 min, global ceiling of 300 failures per minute).                                                                                                                                                                                                                                                 | Simpler than a counter row; also covers recovery-token guessing.                                                                                                           |
| D21 | Lookup, join and token-reclaim failures return a result (`null`, `{ok:false,error}`, `false`) instead of raising.                                                                                                                                                                                                                                                                                            | A raised exception rolls back the failure record, which would disable throttling.                                                                                          |
| D22 | `purge_expired()` and all helpers live in the unexposed `private` schema. Clients can execute only five read-only policy helpers there.                                                                                                                                                                                                                                                                      | The purge is not an API; pg_cron runs it as `postgres`.                                                                                                                    |
| D23 | Vote rounds: `votes.round` with `board_state.base_round`. Ranking uses dots in the base round, then tie rounds after it. A re-vote (F21) opens a new base round with a full budget; earlier rounds stay as visible history. Tie mini-vote rounds give 1 dot among `tie_topic_ids`.                                                                                                                           | One votes table, one visibility rule, and correct budgets after a re-vote (QA finding).                                                                                    |
| D24 | Discussion time spent is wall-clock time while the topic is active, excluding pauses.                                                                                                                                                                                                                                                                                                                        | Matches what the group experienced; simple to book on pause, extend and next topic.                                                                                        |
| D25 | Text from users is cleaned in the database: control, zero-width and bidi-override characters stripped, whitespace collapsed. Markup is stored as-is and escaped at render.                                                                                                                                                                                                                                   | Blocks name spoofing; XSS is handled by React escaping and export escaping.                                                                                                |
| D26 | Local inner loop runs pgTAP on plain Postgres 16 with Supabase stubs (`scripts/db-test-local.sh`). CI runs the same tests on the real Supabase stack and is the gate.                                                                                                                                                                                                                                        | Docker image pulls are blocked in the build container.                                                                                                                     |
| D27 | QA fixes (independent review): per-board passcode cap (20 failures per hour across all identities), minimum passcode 6 characters, global throttle ceiling applies only to callers who are failing, owner cannot be removed, re-reads under the board lock in merge and extend votes, no re-ranking when leaving an already-revealed Vote, global `alter default privileges revoke execute ... from public`. | Each closes a concrete scenario from the review; regression tests added.                                                                                                   |
| D28 | No send policy on `realtime.messages`: clients may receive on `board:<id>` channels but never publish. Presence lives in the database (`heartbeat`).                                                                                                                                                                                                                                                         | Nothing in the app needs client-sent Broadcast, so nobody can spoof one.                                                                                                   |
| D29 | `private.uid()` is VOLATILE.                                                                                                                                                                                                                                                                                                                                                                                 | `supabase db lint` (plpgsql_check) flagged false positives because the planner pre-evaluates stable no-argument calls during estimation.                                   |
